Security invariants: the RPC is SECURITY DEFINER but authenticates `auth.uid()` itself, locks the target row before authorization, requires `visibility='household'`, requires the task's current `assignee_id` to equal `auth.uid()`, and rechecks current membership in that same Household. It accepts only owner ID, client ID and a boolean completion state. The UPDATE statement changes only `completed`, `data.completed`, and `client_updated_at`. Existing owner-only direct UPDATE/DELETE RLS policies are not modified.
